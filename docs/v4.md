# v4 Implementation Plan: PDF Stub & Pipeline Wire-up

**Branch**: `feat/parsing-architecture` (runs in parallel with main roadmap)
**Integration Point**: Merges to `main` upon completion, as all formats are now supported.

---

## Executive Summary

This plan introduces the final piece of the initial `ParserRouter` migration: the `PdfStubParser`. This parser acts as a baseline placeholder for PDF documents, utilizing Docling's default document converter capabilities to extract text before the advanced DeepSeek-OCR2 based `PdfPageRouter` (v5) is built.

Crucially, because v4 achieves full coverage of all supported file types (.txt, .md, .docx, .pptx, .doc, .ppt, and now .pdf), it also handles the **pipeline wire-up**. This means swapping the live `POST /api/v1/documents` endpoint from using the legacy `Parser` to the new `ParserRouter` and `HybridChunker` path. Following this version, the branch is ready to be merged into `main`.

## Phase 1: `PdfStubParser` Implementation

### What is happening
Implement `PdfStubParser` in `core/parsers/pdf_stub.py`. It inherits from the `BaseParser` interface introduced in v1 and handles `.pdf` files. It converts the PDF byte stream into a `DoclingDocument` using Docling's standard PDF conversion utilities. This is a "stub" because it doesn't yet do advanced OCR/VLM per-page routing (which is planned for v5).

### Key Interface Snippet
```python
# core/parsers/pdf_stub.py
from docling_core.types.doc import DoclingDocument
from core.parsers.base import BaseParser

class PdfStubParser(BaseParser):
    SUPPORTED_EXTENSIONS = {".pdf"}

    def can_handle(self, ext: str) -> bool:
        return ext.lower() in self.SUPPORTED_EXTENSIONS

    def parse(self, file_bytes: bytes, filename: str, **kwargs) -> DoclingDocument:
        # Load bytes into docling converter for standard PDF extraction
        result = self._converter.convert_bytes(file_bytes, filename=filename)
        return result.document
```

## Phase 3: Dependency Injection Singleton Update

### What is happening
We must expose `ParserRouter` to the API layer without removing the legacy `Parser` (which must remain for backward compatibility in legacy API routes). We do this by instantiating a singleton `parser_router` in `api/dependencies.py`.

### Key Interface Snippet
```python
# api/dependencies.py
from core import ParserRouter # Imported newly

# Legacy parser remains untouched
parser = Parser()

# New v4 parser router added for v1 endpoints
parser_router = ParserRouter()
```

## Phase 4: Endpoint Pipeline Wire-up

### What is happening
Switch the ingestion endpoint in `api/v1/endpoints/documents.py` to use the new `parser_router` instead of the legacy `parser`. We also update the chunking integration to handle the `DoclingDocument` output and convert the resulting `TextChunk` models into the lists expected by the `retriever.upsert` method.

### Key Interface Snippet
```python
# api/v1/endpoints/documents.py
from api.dependencies import chunker, embeddings, parser_router, retriever, uploader

@router.post("")
async def ingest_documents(...):
    # ... inside ingestion loop ...
    
    # 1. Use the new parser_router
    docling_doc = parser_router.parse(content, filename)

    # 3. Adapt TextChunk models for embeddings and retriever

    metadatas = [c.metadata for c in text_chunks]
    chunk_ids = [c.chunk_id for c in text_chunks]
```
